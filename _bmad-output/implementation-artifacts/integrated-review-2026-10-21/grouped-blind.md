No severity labels or ranking are assigned. Findings concern implemented behavior; Organizations and later NPI-registration placeholders are not counted.

- **Refresh and ping disagree about token freshness.** `lib/server/session/session-routes.ts:65` returns success without refreshing whenever more than 30 seconds remain, while the ping guard at line 111 requires more than 55 seconds. Trigger: click Stay signed in or navigate tabs with 31–55 seconds left. `lib/api/client.ts:253` replays the rejected ping and converts the second TOKEN_EXPIRED into SESSION_EXPIRED. Impact: valid sessions end during ordinary user activity. Minimal fix: coordinate the refresh threshold with the ping threshold, preserving concurrent-refresh deduplication. Existing server tests separately assert the 55-second rejection and no-op refresh, but never compose them.

- **User activity is lost on named-operation writes.** `lib/server/named-op.ts:266` immediately finalizes the operation response without the activity reseal used by `lib/server/proxy/handler.ts`. Trigger: a successful TOTP validation or file deletion carrying X-PP-Activity: user. Impact: lastSeen and the client idle deadline remain unchanged despite an acknowledged write; someone completing such an action near the idle deadline can immediately expire. Minimal fix: apply the shared activity recording contract to successful/forwarded named-operation responses under the existing token-race guard. Trace: `lib/api/client.ts` adds the header to POST/DELETE, `lib/api/mfa.ts` uses the named route, and named-op tests cover token freshness but not activity echoes.

- **A failed identity preflight can become a successful Personal save or upload.** `lib/api/personal.ts:115` (also uploadSignature at line 142, `lib/api/profile-picture.ts:68`, and `lib/api/contacts.ts:259` for contact saves) promotes every failure carrying a 2xx status to success. Trigger: the pinned user's fresh myself preflight answers HTTP 200 with missing/non-numeric id. `lib/api/page-user.ts` correctly returns success:false/statusCode:200, and `callApi` sends no mutation; these resource wrappers then overwrite that failure. Impact: the UI can toast saved, clear its draft and close editing without sending the write. Minimal fix: distinguish a mutation's unreadable 2xx response from a preflight failure in the transport contract, or let endpoints declare empty/non-JSON success handling inside the actual send. Account's wrapper already explicitly preserves this distinction. Tests cover malformed myself in client.test.ts and unreadable write bodies separately, leaving their composition uncovered.

- **A picture upload that leaves the old id visible still reports saved.** `features/header/change-picture-dialog.tsx:156` through line 171 skips the old id during cleanup, caches it, and returns saved even when the post-upload lookup has the same id as before (or null). Trigger: upload returns 2xx but the relation read still returns the old id. Impact: the dialog closes and says Profile picture saved while the avatar continues showing the old picture, with no Retry. Minimal fix: treat an unchanged/missing new id as an unconfirmed replacement and retain Retry, or perform bounded confirmation reads. The existing test at `features/header/change-picture-dialog.test.tsx:507` explicitly reproduces this false success; Signature replacement already rejects an unchanged id.

- **Signature drawings are clipped when the pad narrows.** `features/personal/signature-pad.tsx:81` replays strokes in their original CSS coordinates after resizing the canvas; the remembered strokes carry no source dimensions. Trigger: draw near the right edge of a 400 px pad, then resize/rotate to a 300 px pad or remount below the table/card breakpoint. Impact: strokes beyond x=300 are outside the canvas and the exported signature is incomplete. Minimal fix: retain logical drawing dimensions and scale stroke coordinates/widths into the new viewport (and persist those dimensions with remount memory). The resize unit test currently asserts identical coordinates, so it misses image preservation.

- **Late Places details overwrite newer manual address edits.** `features/addresses/addresses-section.tsx:996` checks only line1 before assigning every returned part at lines 1003–1006. Trigger: choose a suggestion, then edit City, ZIP, State or Country while its details request is pending, leaving line1 unchanged. Impact: the response replaces the user's later entry and sets validated:true. Changing Country only ends the lookup id; it does not invalidate the pending pick token. Minimal fix: invalidate the pick on any relevant manual part/country change, or merge against a full field snapshot and never set Verified over intervening edits. The held-details test at places.test.tsx:551 only changes line1.

- **Auth can schedule a redirect after it unmounts.** `features/shell/auth-screen.tsx:91` awaits runLaunchFlow and then creates the redirect timer; cleanup at line 111 only clears an already-existing timer. Trigger: unmount during the token request/retry delay, then let it succeed. Impact: the stale screen schedules a later location.assign and can redirect the user away from their current page; retries may continue exchanging a stale launch. Minimal fix: use a lifecycle generation/abort signal, check it after awaited work, and stop retries on disposal. The current unmount test at auth-screen.test.tsx:201 unmounts only after success has already created its timer.

- **An unmount while the draft baseline hash is pending loses the draft.** `features/shell/drafts.ts:523` calls writeOrWait for an unregistering dirty Section, then immediately clearTimer/deletes its state; the hash callback rejects state that no longer exists. The provider's flush/dispose cleanup similarly cannot complete a pending hash. Trigger: a Section becomes dirty, its baseline hash is still pending, and the Section/page unmounts. Impact: the promised immediate flush never persists those edits. Minimal fix: retain a captured pending write independently until its hash settles, or ensure a synchronously available base identifier is available before acknowledging the flush. Tests exercise pending-hash flush and unregister-after-hash separately.

- **The idle ping's ten-second cancellation does not bound refresh waiting.** `features/shell/idle-warning.tsx:118` waits for recordUserActivity with an AbortSignal, but `lib/api/client.ts:201` starts refresh without that signal and awaits coordinator.refresh independently. Trigger: ping returns TOKEN_EXPIRED and the refresh request takes longer than ten seconds. Impact: aborting the ping does not settle stay(); pingingRef remains true, so deadline evaluation keeps suppressing session expiry beyond the advertised ten-second bound (an upstream refresh can take 25 seconds). Minimal fix: bound the caller's wait independently of shared refresh without cancelling a refresh needed by other callers; reevaluate the deadline immediately when the ten-second budget expires. Idle tests hold plain ping responses, not ping → refresh.

- **Account accepts the platform's missing-value sentinels as required names.** `features/account/schema.ts:40` calls nameIssue alone, so `n/a`, `N/A` and `-1` pass First/Last name validation and reach updateAccount. Trigger: type one of those values and save. Impact: the platform absence sentinel is persisted as a required name, and the next mapping renders that field as Not provided/empty despite a successful save. Minimal fix: reject isNotProvided values as required, matching Personal's requiredIssue behavior. Account schema tests verify sentinels on read and ordinary name errors, but do not apply sentinels to edited values.

- **Restored partial birth-date drafts disappear from the Personal input.** `features/personal/personal-section.tsx:174` converts the form's display text into a wire date and passes an empty string whenever that text is partial or impossible; it never supplies `DateInput.textValue`. Trigger: type `02/3` or `02/30/1990`, persist the Personal draft, reload, and Restore (or cross the table/card breakpoint while editing). Impact: the input displays blank while the form retains the restored text and validates it as a date-format error, so restoration loses the visible edit and the error refers to hidden content. Minimal fix: pass `textValue={binding.value}` with the existing wire value, using the controlled display-text contract already used by Account. Trace: Personal includes birthDate among draft fields; useSectionForm applies stored strings without requiring a valid date; DateInput resets its internal text from the wire value. Existing Personal tests cover a valid changed birth date and a first-name draft restore, while the shared input fixture explicitly exercises partial/impossible text via textValue.
